> Scale/security update (2026-10-05): `PARTIAL`. The Render blueprint declares the API, maintenance cron, indexer worker, and read-only CI observer in a fixed reviewed profile. Production requires HTTPS origins, trusted hosts, Redis-backed fail-closed traffic protection, bounded Mongo connection pools, and non-development OAuth/encryption secrets. Readiness refuses traffic while Mongo or required Redis traffic protection is unavailable; database recovery recreates correctness-critical indexes before database-backed traffic resumes. Every model call has a bounded context, output, deadline, and retry count; server-side tenant-period token metering records provider-reported usage without trusting browser counters or inventing cost. Provider-reported usage from every graph model call, including structured patch proposals and final answers, is recorded separately so one call cannot hide another. Plan-scoped monthly model-token ceilings reject a new agent run after the observed period budget is exhausted; the current run remains bounded by its context/output limits and tenant agent lease. Low-risk product-guide traffic uses a lower-cost model while repository investigations use the balanced model. Product-guide history is redacted before persistence/model context and is explicitly untrusted. Clerk bearer headers are size-bounded before JWT/JWKS work and the subject is validated before becoming a tenant identity. Repository indexing now has explicit aggregate file, byte, and chunk ceilings, runs its blocking clone/corpus preparation off the worker event loop, deterministically selects the retained subset, and exposes a partial-corpus state rather than claiming complete retrieval coverage. Browser-polled session hydration no longer triggers GitHub/workspace discovery by default; CI is explicitly refreshed or observed post-delivery. Workers drain by stopping new claims on SIGTERM and use short renewable fencing leases; least-privileged workers share only the API-owned Mongo/token-encryption values they need, preventing token-decryption incompatibility. A non-billable k6 staging harness now tests ingress and authenticated reads only; it refuses model, indexing, approval, delivery, and billing surfaces. Live provider/deployment/load verification remains not exercised.
